# Dota Match Analyzer

[English version](README.md)

Интерфейс Streamlit по умолчанию на английском. Переключатель **Language / Язык** справа вверху включает русский; можно также открыть `http://localhost:8501/?lang=ru`. Введённые значения при смене языка сохраняются. Сообщения API — на английском.

Учебный ML-проект: оценка вероятности победы до матча и на пятой минуте. Покрывает Practical Task 6 и SIS-3: scikit-learn, FastAPI, Uvicorn, Docker, Streamlit, MLflow Tracking и Model Registry. Два режима используют независимые исторические наборы и отдельные модели.

## Новый режим: пять минут

На первой вкладке выберите по пять героев Radiant и Dire и заполните **суммы по пяти игрокам каждой команды на отметке 5:00**: gold/net worth, XP, last hits, kills, deaths, уровни и число покупок items. Gold означает ценность героев с предметами, а не свободное золото. Items означает число покупок в течение первых пяти минут, а не количество занятых слотов. Незаданные показатели остаются пустыми и блокируют прогноз. Кнопка «Загрузить показатели примера» заполняет реальную запись из обучающей части; её нельзя считать проверкой качества.

Источник: набор YASP/Coursera из 97 230 матчей, описанный в [исходном задании](https://github.com/romovpa/kaggle-dota2-contest). CSV взят из [открытого зеркала](https://github.com/nikkuper/coursera-dota-2) с закреплённым commit и SHA-256 в data/early/SOURCE.json. Атрибуция и CC BY-SA 4.0 — в data/early/ATTRIBUTION.md. Данные UCI не объединяются с этим CSV: у них нет надёжного общего идентификатора.

| На одинаковом временном тесте из 14 585 матчей | Только герои | Герои + первые 5 минут |
|---|---:|---:|
| Accuracy | 58.16% | **68.97%** |
| ROC AUC | 0.6069 | **0.7547** |

Это +10.82 процентного пункта на одной и той же выборке. Прежние 60.37% относятся к другому набору UCI и напрямую с 68.97% не сравниваются. На пятой минуте модель получает больше информации, поэтому задача отличается от прогноза до игры.

Разбиение нового набора: первые 70% по start_time — fit, следующие 15% — validation, последние 15% — итоговый Test. Порядок стабилизируется match_id. Идентификаторы уникальны, один матч не попадает в разные части. В исходном наборе timestamps слегка изменены для анонимизации: это порядок по опубликованным меткам, а не точная реальная хронология. Финальный выбор по validation ROC AUC, затем переобучение на первых 85%. Сравниваются baseline, две модели только по героям, три Logistic Regression со статистикой и два варианта HistGradientBoosting. Тест не участвует в выборе.

В признаки передаются 113 знаковых индикаторов героев, 14 командных сумм и 7 разностей между командами; числовые показатели стандартизируются только по обучающей части. Явный allowlist исключает radiant_win, duration, итоговые tower_status/barracks_status, match_id и start_time. Другие доступные в CSV признаки также не используются. Исходный набор содержит матчи длительностью не менее 15 минут; это ограничение выборки, а не гарантия для произвольного современного матча.

Обучение: `python train_early.py`. Оно сохраняет models/early_model.joblib и models/early_metrics.json, пишет отдельный эксперимент **Dota Minute Five**, регистрирует **DotaMinuteFiveClassifier** и назначает alias champion. Существующая модель драфта сохраняется. После обучения перезапустите API. Если CSV удалён, `python download_early_data.py` скачает закреплённое зеркало и проверит SHA-256.

API нового режима:

- GET /early/metadata — доступные герои, примеры без исхода, результаты сравнения.
- GET /early/health — готовность модели пятой минуты.
- POST /predict/early — снимок с snapshot_seconds=300 и двумя объектами radiant/dire. Каждый содержит heroes (5 ID) и обязательные целые неотрицательные gold, xp, lh, kills, deaths, level, items. Неизвестные герои, повторы, пропуски, итоговые поля и другое время отклоняются.

Минимальный PowerShell-пример с реальной записью Train:

```powershell
$meta = Invoke-RestMethod http://localhost:8000/early/metadata
$body = $meta.examples[0] | ConvertTo-Json -Depth 5
Invoke-RestMethod http://localhost:8000/predict/early -Method Post -ContentType application/json -Body $body
```

## Данные и ограничения

Источник: [Stephen Tridgell, Dota2 Games Results, UCI, 2016](https://archive.ics.uci.edu/dataset/367/dota2+games+results), [DOI](https://doi.org/10.24432/C5W593), лицензия CC BY 4.0. CSV включены в `data/` без изменения исходных файлов. Данные собраны 13 августа 2016 года за два часа. Это исторический учебный прототип; модель не оценивает современную мету и не знает навыки игроков, предметы, линии и ход игры.

В CSV **нет заголовка**. Каждая из 117 колонок: результат (+1/-1), cluster ID, код режима, код типа игры, затем 113 индикаторов героев. Значение +1 означает героя команды A, -1 команды B, 0 отсутствие героя. На каждой стороне ровно пять героев. Используются обозначения A/B, потому что описание UCI не подтверждает соответствие сторон Radiant/Dire. Названия героев приведены к знакомому английскому написанию с сохранением Valve ID. Неактивные в Train ID 24 и 108 исключены из интерфейса. ID — не порядковый номер строки списка.

92 650 матчей Train, 10 294 Test. Из входных признаков исключены результат и cluster ID. Коды режима и типа игры обрабатываются как категории, индикаторы героев передаются численно. Современные названия режимов не подставляются без подтверждения.

## Быстрый запуск на Windows

Нужен Python 3.12. Откройте терминал **в папке проекта**. `requirements.txt` автоматически подключает `constraints-tested.txt` с версиями всех зависимостей проверенного окружения; pywin32 ограничен Windows:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe train.py
.\.venv\Scripts\python.exe train_early.py
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

В другом терминале в той же папке:

```powershell
.\.venv\Scripts\python.exe -m streamlit run frontend.py
```

В третьем терминале для просмотра экспериментов и Registry:

```powershell
.\.venv\Scripts\python.exe -m mlflow ui --backend-store-uri sqlite:///tracking/mlflow.db --host 127.0.0.1 --port 5000
```

- Интерфейс: http://localhost:8501
- API и проверка жизни: http://localhost:8000/
- Swagger: http://localhost:8000/docs
- MLflow: http://localhost:5000

Файлы `models/model.joblib` и `models/metrics.json` создаёт train.py; `models/early_model.joblib` и `models/early_metrics.json` создаёт train_early.py. Обе обученные модели включены в архив: для запуска API повторное обучение можно пропустить. Для создания истории MLflow на другом компьютере запустите обучение заново: локальное хранилище MLflow использует пути текущей машины.

## Docker

Для автоматической проверки на Windows после установки Docker Desktop запустите `./verify-docker.ps1`. Он использует отдельные порты и docker-state/, выполняет обучение и тесты в контейнерах и сохраняет реальный статус в docker-evidence/. После успешной сборки и обучения можно повторить только проверку сервисов командой `./verify-docker.ps1 -Resume`: она пересоздаёт контейнеры, проверяет готовность HTTP и совпадение версии API с champion в Registry. Первичная настройка Windows описана в [DOCKER-SETUP.md](DOCKER-SETUP.md). Если Docker или WSL ещё не установлены, скрипт возвращает BLOCKED, а не имитирует успешную проверку.

Нужен работающий Docker Desktop с Linux containers. Из папки проекта:

```powershell
docker compose build
docker compose run --rm train
docker compose run --rm train-early
docker compose up -d --force-recreate api frontend mlflow
docker compose ps
```

Обучение запускается отдельным сервисом, не при каждом запросе и не при сборке образа. `data`, `models`, `tracking` и `mlruns` подключены через volumes. Обучение в Docker создаёт историю MLflow с контейнерными путями. Для проверки локальной Windows-версии и контейнерной версии используйте отдельные копии проекта либо отдельные каталоги `tracking`/`mlruns`: SQLite с абсолютными путями не переносится между ОС автоматически.

```powershell
docker compose logs api
docker compose down
```

Для запуска только API из образа после обучения:

```powershell
docker run --rm -p 127.0.0.1:8000:8000 --mount "type=bind,source=$($PWD.Path)/models,target=/app/models,readonly" dota-draft-analyzer:local
```

## Запрос к модели

`POST /predict`:

```json
{
  "team_a": [1, 2, 3, 4, 5],
  "team_b": [6, 7, 8, 9, 10],
  "game_mode": 2,
  "game_type": 2
}
```

Ответ содержит `team_a_probability`, `team_b_probability`, `predicted_winner`, имя и версию модели и историческую оговорку. Вероятности в сумме равны 1. Модель использует порог 0.5. Вероятности являются оценками классификатора и не обещают строгой калибровки.

В PowerShell:

```powershell
$body = @{team_a=@(1,2,3,4,5); team_b=@(6,7,8,9,10); game_mode=2; game_type=2} | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8000/predict -Method Post -ContentType application/json -Body $body
```

## Советник пиков

Раздел **Советник пиков** подсказывает следующего героя для незавершённого драфта. Укажите уже выбранных героев (любое количество, можно ни одного), команду, которая пикает следующей, и нажмите **Подобрать героя**. Кнопка **Взять** добавляет героя в команду, так что драфт можно собрать по шагам. Ничего не переобучается: используется та же зарегистрированная модель драфта.

Как это работает (recommend.py): каждый свободный герой пробуется как следующий пик. Модели нужен полный драфт 5 на 5, поэтому пустые слоты 50 раз заполняются случайными свободными героями, а вероятности усредняются (метод Монте-Карло); у всех кандидатов одинаковые случайные заполнения, что снижает шум в разнице. Если кандидат завершает драфт, оценка точная. «vs случайный пик» — разница со средним по всем кандидатам. Каждая рекомендация объясняется весами логистической регрессии: сила героя, синергия с союзниками и противостояние с выбранными противниками; тест проверяет, что сумма весов точно совпадает с изменением логарифма шансов модели.

`POST /recommend` принимает `team_a`, `team_b` (0–5 героев), `side`, `game_mode`, `game_type`, `top`. Ограничения: модель обучена на матчах 2016 года и имеет ROC AUC 0.64, поэтому разница в 1–2 пункта — в пределах шума; это мнение модели, а не совет для современной меты.

`GET /metadata` возвращает доступных героев, режимы, параметры качества и версию. `GET /health` возвращает 503, если модель не загружена. При отсутствии модели `/` и `/docs` остаются доступны. После первого обучения перезапустите API. Десять героев должны быть уникальными; неизвестные ID, лишние поля и нецелые значения отклоняются с HTTP 422.

## Обучение и честная оценка

1. Проверяются формат CSV, пропуски, кодировки значений и размер составов.
2. Внутри Train выделяется 20% групп для валидации с seed 42. Одинаковые признаки матча попадают в одну группу, чтобы не дублироваться между fit и validation. Группировка может немного изменить пропорцию классов.
3. Сравниваются baseline с постоянной вероятностью, Logistic Regression с C=0.1 и C=1, Random Forest и четыре регуляризованных модели с парными признаками. Парные признаки кодируют союзные пары (плюс для A, минус для B) и противостояния героев (знак меняется при смене сторон). Имена игроков и результаты для построения этих признаков не используются. Основные признаки масштабированы в 10 раз относительно пар, чтобы сильнее регуляризовать редкие сочетания. Выбор — по validation ROC AUC. Если сложные модели не превосходят baseline, baseline также может победить.
4. Победитель переобучается на полном Train. Только затем считается итоговый результат на исходном Test.
5. В отчёте есть accuracy, precision, recall, F1, ROC AUC, log loss, Brier score, матрица ошибок, сравнение с baseline и пересечение признаков Train/Test. Метрики на Test без пересечений приводятся отдельно, если такие строки есть. F1 считается для победы A: baseline, всегда выбирающий A, может иметь более высокий F1 при плохом различении классов. Поэтому выбор модели опирается на ROC AUC, а оценка включает несколько метрик.
6. Сохраняются SHA-256 обоих исходных CSV, дата обучения и полный порядок входных признаков.

Каждая модель создаёт отдельный validation run в MLflow. Final run содержит итоговые параметры, метрики, артефакт модели, JSON-отчёт и графики `plots/roc_curve.png` и `plots/confusion_matrix.png` на Test (для пятой минуты дополнительно `plots/draft_only_*` модели только по героям). Модель регистрируется как `DotaDraftClassifier`, получает автоматически возрастающую версию и alias `champion`.

### Загрузка модели из Registry

По умолчанию API загружает экспортированный файл `models/*.joblib` один раз при старте. Если задать `MODEL_URI` и/или `EARLY_MODEL_URI`, API берёт модель из MLflow Model Registry — ту версию, на которую указывает alias, а метаданные — из `metrics.json` того же run:

```powershell
$env:MODEL_URI = "models:/DotaDraftClassifier@champion"
$env:EARLY_MODEL_URI = "models:/DotaMinuteFiveClassifier@champion"
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Можно указать и конкретную версию: `models:/DotaDraftClassifier/2`. Откуда загружена модель, показывает `GET /` (`model_source`), номер версии — `GET /metadata` и ответ `/predict`. Чтобы откатиться или выкатить другую версию, переставьте alias `champion` в MLflow UI и перезапустите API. Горячая перезагрузка без перезапуска не заявляется.

Версия 2 использует парные признаки: на том же официальном Test accuracy выросла с 59.724% до 60.365%, ROC AUC с 0.63458 до 0.64399. Это 66 дополнительных верных прогнозов на 10 294 матчах. Прирост небольшой: точный тест Мак-Немара даёт p≈0.052, поэтому устойчивое улучшение на других матчах пока не доказано. Test уже использовался для отчёта v1; при улучшении параметры выбирались исключительно по Train/validation, а затем один выбранный вариант был проверен на том же фиксированном Test.

`python train.py --basic` воспроизводит исходное сравнение без парных признаков. `python tune.py` запускает дополнительное исследование бустинга, парных признаков и MLP исключительно на Train, сохраняет JSON и не заменяет модель API. Результаты выполненного поиска сохранены в `models/improvement_search.json` и `models/improvement_extended.json`.

## Проверки

После обучения:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Проверяется совпадение признаков обучения и API на реальном матче, результат HTTP с настоящей сохранённой моделью, `/docs`, ошибки ввода, недоступность модели и состав справочника. Фактически выполненные проверки и метрики см. в `VALIDATION.md`.

## Что показать на защите

Откройте интерфейс, загрузите пример и получите прогноз. Измените одного героя и пересчитайте. Покажите отклонение повторного выбора героя. Откройте Swagger и выполните POST-запрос. На вкладке качества сравните baseline с обученными моделями. В MLflow покажите validation runs, final run, параметры, метрики, модель и её версию в Registry. Объясните ограничения исторических данных и разделение Train/validation/Test.

Для сдачи требуется самостоятельно создать Git-репозиторий и загрузить проект. Публикация в аккаунт пользователя в рамках подготовки исходников не выполнялась. Не добавляйте в Git локальные `tracking/`, `mlruns/` и виртуальное окружение.
